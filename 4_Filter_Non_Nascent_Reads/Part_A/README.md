# Stage 4A: detect conversions and filter BAMs

Part A locates conversion-bearing read names while accounting for base quality,
read-end trimming, and known SNPs, then extracts those read pairs into a new
BAM.

## Scripts

### `4A_SLAM_Seq_Script_Filter.sh`

The SLURM array driver validates the sample list, Stage 3 SNP union, Python
script, and Stage 2 BAM. It runs `splbam.py` using the conversion and filtering
settings from `config.sh`, then uses the generated true-conversion read-name
list with `samtools view -N`. Finally, it coordinate-sorts and indexes the
filtered BAM and deletes the unsorted intermediate.

The checked-in job requests 48 CPUs and 400 GB of memory for each of 28 tasks.
Tune both the SLURM request and `SPLBAM_MEMORY` for the target cluster.

### `splbam.py`

This command-line program processes BAM contigs in parallel with `pysam`. It:

- determines transcript orientation using a hard-coded RF-first-strand rule;
- gathers mismatches and per-position mismatch summaries from MD-tagged
  alignments;
- selects the configured reference-to-conversion event (T-to-C by default,
  representing antisense A-to-G events in the same orientation);
- removes low-quality, configured read-end, and known-SNP events;
- adjusts the reported conversion counts after filtering; and
- writes mismatch tables plus the unique read names with at least one retained
  conversion.

Its required positional arguments are `bam`, `outdir_mm`, and `name`. Run
`python splbam.py --help` for optional SNP/VCF, quality, trimming, logging,
parallelism, memory, temporary-directory, and SLURM-submission options.

The script describes labelled/unlabelled BAM splitting in its inherited help
text, but in this pipeline it emits read lists and tables; the shell driver
performs the BAM extraction.

### `utils.py`

Support module used by `splbam.py`. It supplies logging arguments, file and
program checks, subprocess helpers, SLURM submission options, parallel map
helpers, BAM sort/index checks, and VCF-to-location conversion. It is a library,
not a standalone pipeline stage.

## Inputs

- `HISAT3N_OUTPUT_DIR/<sample>_aligned.unique.sorted.bam` and its index;
- `SNP_OUTPUT_DIR/SNP_UNION_OUTPUT` from Stage 3; and
- a sample stem selected from `SAMPLE_FILELIST`.

## Outputs

Mismatch data are written under `HISAT3N_OUTPUT_DIR/mismatch_infos`:

- `<sample>.mismatchDetails.tab.gz`: mismatch counts by position;
- `<sample>.mismatches.tab.gz`: aggregate mismatch counts before conversion
  filters;
- `<sample>.mismatches-used.tab.gz`: selected conversion counts after filters;
- `<sample>.mismatch_all_final_list.tab.gz`: every retained conversion record;
- `<sample>.trueconversions_list.tab`: read names with retained conversions;
- `<sample>.Yf.table.<category>.tab`: mutation-category lists when supplied by
  the mismatch tooling/workflow; these are expected by Part B.

The shell driver creates
`HISAT3N_OUTPUT_DIR/<sample>_aligned.unique.filtered.sorted.bam` and its `.bai`
index. Note that the checked-in `splbam.py` directly creates the first five
listed outputs; it does **not** visibly create the `Yf.table` category files,
so Part B requires those files to be generated by an additional compatible
step or supplied from the original workflow.
